# Libevent 2.1.13 compat package

- Source: `libevent/libevent`, latest stable tag observed `release-2.1.13-stable` (2.2 tags were alpha prereleases); GitHub tag archive SHA-256 `1a0885e17dc78afbaeddf13cf849f9238bbc24acdc178464a0d1934d7c5ffbd5`, calculated twice.
- Shape: Form B, C source package. The release needs `event2/event-config.h` and `evconfig-private.h` generated by CMake feature probes. `install()` invokes declared `xim:cmake` only to produce those platform headers; mcpp compiles the upstream C translation units so the library follows the consumer's toolchain. Its source list mirrors CMake's `SRC_CORE` and `SRC_EXTRA`, plus the per-platform backends (Linux epoll, macOS kqueue, Windows IOCP/select), and POSIX/Win32 threading. TLS integrations are not part of the default library and are deliberately excluded, not exposed as unverified features.
- Platforms: linux, macosx, windows all declared against the same archive and sha256. The test member executes the same event timer, evbuffer round trip, and HTTP object construction on each. Windows system libraries are explicitly linked.
- License: BSD-3-Clause for the main sources, ISC for arc4random included by `evutil_rand.c`, and MIT for the Windows timer code derived from libutp (`evutil_time.c`; see upstream LICENSE). The separate wepoll and TLS integrations are not compiled.
- Mirror: no GitCode credentials/assets available; use a plain upstream URL (not a fictional CN URL).
- Verification: pending matrix on macOS/Windows. On local Linux GCC 16.1.0 using mcpp 2026.10.1.2, `mcpp xpkg parse --all-os pkgs/c/compat.libevent.lua` reports 24/24/25 sources; cold `mcpp test -p libevent --cache off` passed after switching the test to a single-event loop (`EVLOOP_ONCE`); the first test incorrectly assumed `event_base_dispatch()` returns zero after a one-shot timer (it returns one when the queue empties, even though the callback fired).
